# Serverless Cloud Resume Challenge (AWS & Terraform)

A full-stack, serverless personal resume deployed on AWS using Infrastructure as Code (IaC) with Terraform and automated via GitHub Actions with passwordless OpenID Connect (OIDC) authentication.

## Key Architectural Components

- **Edge Delivery & Storage**: Amazon S3 stores raw static assets (`index.html`, `style.css`, `script.js`). Public access is blocked; Amazon CloudFront delivers assets globally using Origin Access Control (OAC) with automatic HTTP-to-HTTPS redirection.
- **Serverless Compute**: AWS Lambda running Python 3.11 executes backend logic behind an Amazon API Gateway HTTP API proxy route (`GET /visitors`).
- **Atomic State Storage**: Amazon DynamoDB retains visitor metrics using atomic counter updates (`ADD #c :inc`) to prevent race conditions during concurrent hits.
- **Infrastructure as Code (IaC)**: 100% defined in modular Terraform configurations for automated provisioning and tearing down.
- **Continuous Integration & Delivery (CI/CD)**: GitHub Actions workflows validate backend logic using moto mocks and sync frontend assets securely via AWS STS OIDC federation.

## CI/CD Pipeline & Automated Testing

### 1. Backend Verification (`backend-deploy.yml`)

- **Isolated Cloud Mocking**: Runs pytest against mocked AWS infrastructure via moto without incurring AWS service charges or touching production tables.
- **Integrity Validation**: Verifies table creation, item addition, schema parsing, and fallback exception handling before any code merges into `main`.

### 2. Passwordless Deployment (`frontend-deploy.yml`)

- **No Long-Lived Credentials**: Replaces permanent `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY` secrets with dynamic JSON Web Tokens (JWT) generated by GitHub Actions.
- **Secure Token Exchange**: The runner requests a short-lived token from AWS STS via `sts:AssumeRoleWithWebIdentity`, syncs files to S3, and creates a CloudFront edge cache invalidation (`/*`).

## Engineering Hurdles & Troubleshooting

### 1. GitHub Actions OIDC Claim Token Mismatches (`sub` Claim)

**Issue**: GitHub Actions failed to assume the IAM deployment role, throwing:

```text
Error: Could not assume role with OIDC: Not authorized to perform sts:AssumeRoleWithWebIdentity
```

**Root Cause**: By default, GitHub Actions includes internal account and repository IDs directly inside the subject claim string:

```json
"sub": "repo:amrit-pratya@183978349/Cloud-Resume-Challenge-@1371218745:ref:refs/heads/main"
```

A standard IAM string match against `repo:amrit-pratya/Cloud-Resume-Challenge-:*` evaluated to `false`.

**Resolution**: Decoded the raw JWT payload within the workflow runner to inspect the exact incoming claims and updated the IAM Trust Policy condition to handle embedded IDs using wildcards:

```json
"StringLike": {
  "token.actions.githubusercontent.com:sub": "repo:amrit-pratya*/Cloud-Resume-Challenge-*:*"
}
```

### 2. API Gateway HTTP 500 & Silent Execution Failures

**Issue**: Direct requests to `/visitors` resulted in HTTP 500 Internal Server Error, while manual tests inside the AWS Lambda console returned HTTP 200 OK. No CloudWatch logs were produced for HTTP calls.

**Root Cause**: The `aws_lambda_permission` resource in Terraform was provisioned using the generic API Gateway ARN (`aws_apigatewayv2_api.http_api.arn`) instead of the invocation execution ARN.

**Resolution**: Pointed `source_arn` to `${aws_apigatewayv2_api.http_api.execution_arn}/*/*`. This granted API Gateway proper authorization to execute the Lambda proxy target.

### 3. Reserved Lambda Runtime Environment Variables

**Issue**: Applying Terraform changes resulted in an `InvalidParameterValueException`:

```text
Lambda was unable to configure your environment variables because the environment variables you have provided contains reserved keys: AWS_REGION
```

**Root Cause**: `AWS_REGION` is reserved by the AWS Lambda runtime and automatically injected into execution environments.

**Resolution**: Removed manual declarations of `AWS_REGION` from the Terraform `environment.variables` block while retaining fallback checks in Python (`os.environ.get("AWS_REGION", "us-east-1")`).

## Deployment Instructions

### Prerequisites

- Terraform (>= 1.5.0)
- AWS CLI configured locally
- Python 3.11

### Step 1: Clone Repository

```bash
git clone https://github.com/amrit-pratya/Cloud-Resume-Challenge-.git
cd Cloud-Resume-Challenge-
```

### Step 2: Deploy Infrastructure via Terraform

```bash
cd terraform
terraform init
terraform apply -var="github_repo=amrit-pratya/Cloud-Resume-Challenge-"
```

### Step 3: Configure GitHub Actions Secrets

In your GitHub repository settings under **Secrets and variables > Actions**, configure:

- `AWS_ROLE_ARN`: The ARN of your `github-actions-cloud-resume` IAM role
- `S3_BUCKET_NAME`: The generated bucket ID from Terraform outputs
- `CLOUDFRONT_DIST_ID`: The CloudFront distribution ID from Terraform outputs

### Step 4: Run Tests Locally

```bash
pip install pytest boto3 moto
export PYTHONPATH=.
pytest backend/tests/
```
